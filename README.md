# 🎓 EduCenter Pro — نظام إدارة المركز التعليمي

نظام متكامل لإدارة المراكز التعليمية ومراكز الدروس الخصوصية، مبني بـ React 19 + TypeScript + Vite + Tailwind CSS 4.
بيشتغل محلياً (IndexedDB) كتطبيق ويب / PWA / تطبيق سطح مكتب (Electron)، ومعاه مزامنة سحابية اختيارية عبر Supabase.

> 🧱 دليل الهيكل الحالي وقواعد التطوير في [`docs/ARCHITECTURE_AR.md`](docs/ARCHITECTURE_AR.md).
>
> 📄 وثيقة التدقيق التاريخية وخارطة الطريق الكاملة (بالعربي) في [`docs/SYSTEM_AUDIT_AR.md`](docs/SYSTEM_AUDIT_AR.md).

## ✨ المميزات

### 👨‍ الطلاب
- إضافة/تعديل/حذف (الحذف soft-delete — السجل بيتعلّم `deleted` ولا يُمسح فعلياً)
- بحث وتصفية بالاسم والحالة + **بحث شامل** في كل الكيانات
- ملف شامل للطالب: المجموعات، الأقساط، المدفوعات، الحضور، سجل التحويلات
- **فحص التكرار** بالاسم/التليفون قبل الإضافة + رفع صورة للطالب
- استيراد/تصدير CSV

### 👨‍🏫 المدرسون
- بيانات + إحصائيات (مجموعات/طلاب) + ملف شامل للمدرس
- **نماذج أجر متعددة**: نسبة من اشتراك الطالب كاملاً / ثابت / بالحصة / نسبة من المحصّل / لكل مجموعة

### 💵 مرتبات المدرسين
- قسم شهري مستقل للمسؤول والمحاسب، مع **نسبة مختلفة لكل مدرس**
- نسبة من **كامل اشتراك الطالب المسجل** حتى لو لم يدفع، مع تفصيل نصيب المدرس من كل طالب ومجموعة
- اعتماد كشف الشهر كلقطة ثابتة تحفظ النسبة والتفاصيل، ثم صرف كلي أو جزئي مع سند تلقائي في المصروفات
- عرض المستحق والمصروف والمتبقي، فلاتر المدرس والشهر والحالة، وطباعة كشف إجمالي أو تفصيلي
- الإعدادات القديمة لا تتغير تلقائياً؛ اختر «نسبة من اشتراك الطالب» وحدد النسبة لكل مدرس
- [دليل الاستخدام وقواعد الحساب وترحيل Supabase](docs/TEACHER_PAYROLL_AR.md)

### 📚 الكورسات والمجموعات
- كورسات بمستويات ديناميكية وأسعار وألوان
- مجموعات مربوطة بكورس ومدرس + جدول أسبوعي + سعة
- **كشف تعارضات الجدول** (مدرس/قاعة في وقتين) على لوحة التحكم

### 💰 المال والتحصيل
- دفعات (اشتراك/كتب/أخرى) بحالات (مدفوع/معلق/متأخر) + **طريقة دفع** و**اسم المحصِّل**
- **إيصالات متسلسلة** (بادئة + عدّاد) قابلة للطباعة RTL
- **إلغاء/استرجاع (Void & Refund)** بأثر محاسبي صحيح على الإيراد
- **خصومات وتجاوز سعر** (price override) لكل تسجيل
- **رصيد دائن/مدين** للطالب وترحيله بين المجموعات عند التحويل
- **خطة أقساط شهرية** تلقائية لكل تسجيل + دفع جزئي/كامل + توزيع على الأقدم
- **تاريخ استحقاق قابل للإعداد** (يوم من الشهر + أيام سماح) + تذكيرات بالمستحق قريباً
- **عدد حصص الشهر قابل للإعداد** (افتراضي 8) وتسعير بالحصص عند الالتحاق منتصف الكورس
- صفحة **المديونيات** بفلاتر وتحصيل سريع وتذكير واتساب
- **تصفير المديونيات (إبراء ذمة)**: إلغاء الأقساط غير المسددة بنطاقين (كل المتبقي / المستحق والمتأخر فقط) بنافذة تأكيد فيها ملخص الأرقام وسبب إلزامي وكتابة كلمة «تصفير» — والدفعات المحصّلة ما بتتمسش وتبقى **رصيد دائن**
- **التقرير اليومي**: إجمالي التحصيل بطريقة الدفع وبالموظف، الاستردادات والمصروفات وصافي الكاش
- تقارير مالية **بمدى تاريخ مخصص** + تقرير تقادم الديون

### ✅ الحضور والاختبارات
- حضور/غياب/تأخير/استئذان + وقت دخول/خروج + ملخص
- **sheets حضور قابلة للطباعة**
- اختبارات ودرجات ومتوسطات

### 📊 التقارير والداشبورد
- لوحة تحكم برسوم بيانية + عدّادات + أعلى المديونيات + تنبيهات التعارض
- تقارير: مالي، حضور، مجموعات، مدرسين، تقادم ديون — كلها **بطباعة RTL سليمة** عبر المتصفح

### 🔐 المستخدمون والصلاحيات
- تسجيل دخول بـ bcrypt + Rate limiting + انتهاء جلسة + تغيير كلمة المرور الافتراضية/المطلوبة قبل دخول الصفحات المحمية
- الجلسة المسترجعة تُراجع مقابل المستخدم المحلي الحالي؛ إعادة تعيين القاعدة من شاشة الدخول تتطلب بيانات مسؤول وتأكيد الحذف
- **أدوار وصلاحيات granular** (مصفوفة كيان × إجراء في `src/lib/permissions.ts` — المسارات والأزرار كلها بتتحكم منها):

  | الدور | بيقدر |
  |---|---|
  | **مسؤول** | كل حاجة |
  | **استقبال** | تسجيل/تعديل الطلاب، تحصيل الدفعات، الحضور، عرض المديونيات والمجموعات — من غير مصروفات/استرداد/حذف/إعدادات |
  | **محاسب** | المدفوعات والاستردادات والمديونيات والمصروفات ومرتبات المدرسين والتقارير والتقرير اليومي وسجل المراجعة — من غير تعديل أكاديمي |
  | **مشرف أكاديمي** | الطلاب والمجموعات والكورسات والحضور والاختبارات وتقارير العرض — من غير أي أرقام مالية |
  | **مدرس** | مجموعاته هو بس: حضور ودرجات وعرض طلابه — من غير أي أرقام مالية |

- **نطاق رؤية للمدرس**: حساب المدرس مربوط بسجله (`teacherId`) وبيشوف مجموعاته هو بس في لوحة التحكم والطلاب والحضور والاختبارات

### 🛠️ التشغيل اليومي
- **روابط واتساب مباشرة** لولي الأمر من الحضور/المديونيات/ملف الطالب (تذكير غياب/مستحقات)
- **مخزون** (ملزمات/كتب) بحركات وتنبيه نقص مخزون
- **نسخ احتياطي** يدوي وتلقائي يومي + استيراد JSON
- **سجل مراجعة (Audit Log)** في IndexedDB بكل العمليات + بحث وتصدير

### ⚙️ الإعدادات
- اسم المركز، الألوان، الخطوط، الشعار، تذييل الإيصال، بادئة الإيصال
- يوم الاستحقاق، أيام السماح، حصص الشهر، تنبيهات المتأخر/المستحق، حد نقص المخزون

## 🆕 أبرز ما أُضيف في هذه النسخة (خلاصة التدقيق)

| المجال | ما تم |
|---|---|
| أمان/بيانات | RLS مقتصرة على authenticated، حذف ملف PII من الشجرة، سكربت تطهير التاريخ، حارس CI ضد رفع بيانات حقيقية |
| مزامنة | إعادة كتابة المزامنة: سحب مُرقَّم (pagination) + دمج per-row بدل مسح-وشحن (كان بيمسح بيانات) |
| سجل المراجعة | نقله من localStorage إلى IndexedDB (`audit_logs`) مع ترحيل تلقائي |
| إيصالات | عدّادات متسلسلة في store `counters` + طباعة RTL بدل jsPDF المكسور |
| مطابقة الاستيراد | مطابقة الطلاب بالتليفون ثم بالاسم الموحّد + كشف الأسماء المكررة الغامضة |
| طباعة | `src/lib/printing.ts` — جداول وإيصات HTML تُطبع عبر المتصفح (RTL سليم) |
| PWA | `manifest.json` + أيقونات مولّدة + `sw.js` فعّال (أوفلاين) |
| DevOps | GitHub Actions CI فعّال (typecheck → lint → architecture → test → PII-guard → build) + LICENSE |
| تصفير المديونيات | `writeOffDebts(scope, reason)` في `src/services/debtWriteOffService.ts` (مع واجهة توافق في `lib/db.ts`) + نافذة تأكيد في صفحة المديونيات + حدث `writeoff` في سجل المراجعة |

## 🚀 التشغيل

### المتطلبات
- Node.js 22+ و npm (أدوات التطوير والاختبارات محتاجة Node 22؛ التطبيق نفسه بيشتغل في المتصفح)

### التثبيت والتطوير
```bash
npm ci
npm run dev          # خادم تطوير
npm run test         # الاختبارات (Vitest)
npm run verify       # أنواع + lint + حدود الطبقات + اختبارات + حارس الملفات + بناء
npm run build        # فحص أنواع + بناء للإنتاج (ملف واحد dist/index.html)
```

### سطح المكتب (Electron)
```bash
npm run electron:dev        # تطوير
npm run electron:build:win  # حزمة ويندوز   (وكذلك :linux / :mac / :all)
```
الأيقونات (`build/icon.png|ico|icns`) مولّدة عبر `node scripts/make-icons.mjs`.

### Docker
```bash
docker-compose up -d
```
(فيه `Dockerfile` multi-stage و `nginx.conf` جاهزين للاستضافة الذاتية.)

## 🗄️ التخزين

محلياً: **IndexedDB** (مكتبة `idb`). الجداول (stores):
`students, teachers, courses, groups, enrollments, installments, payments, refunds, counters,
attendance, exams, grades, expenses, cashbox_sessions, payroll, teacher_advances,
inventory, inventory_transactions, users, settings, audit_logs, message_logs, message_templates, waitlist`

> الجداول `cashbox_sessions / teacher_advances / message_* / waitlist` موجودة في المخطط (وبتتزامن) للحفاظ على توافق النسخ الاحتياطية، لكن مفيش شاشات إدخال مستقلة ليها في هذه النسخة. `payroll` له شاشة مرتبات مستقلة، وتخصم السلف المسجلة عند اعتماد الكشف.

### ☁️ Supabase (اختياري)
1. أنشئ مشروعاً وشغّل [`supabase_schema.sql`](supabase_schema.sql) (يفعّل RLS لـ authenticated فقط).
2. انسخ `.env.example` إلى `.env` وعبّئ `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY`.
3. أنشئ حساب Supabase Auth مخصصاً للمركز، وأدخل بريده وكلمة مروره في قسم السحابة داخل إعدادات التطبيق. المزامنة تستخدم حساب المركز، وليس تسجيل دخول مجهولاً.

> 🔒 الـ RLS تعزل كل مركز باستخدام `tenant_id` المرتبط بحساب Supabase Auth. جدول `users` محلي ولا يُرفع للمزامنة؛ حساب المركز السحابي مختلف عن مستخدمي البرنامج وأدوارهم المحلية.
> لا تعطّل RLS — بدونها أي حامل anon key يقرأ ويعدّل كل البيانات.

> ⚠️ البيانات محلياً في متصفحك؛ مسح بيانات المتصفح يفقدها — اعمل نسخاً احتياطياً دورياً من الإعدادات.
